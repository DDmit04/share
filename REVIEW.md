# Ревью: скраперы и алгоритм похожести имён

> Статический анализ: shell в этой сессии заблокирован (`spawn EPERM`), поэтому код не запускался.
> Все выводы — по чтению исходников. Ссылки на строки указаны по текущему состоянию файлов.

```

                 │

```

Нормализация кодов существует **в двух почти независимых реализациях**:

- `compare/compare.py:extract_bearing_codes` — используется всеми скраперами (`bearing_similarity`);
- `compare/extract.py:extract_bearing_number` — не импортируется нигде (мёртвый код), при этом с теми же
  ошибками в регулярках и с docstring-примерами, которые не выполняются.

## 2. Алгоритм похожести: что он реально считает

`bearing_similarity(desc, src)` (`compare/compare.py:158`):

1. `remove_bearing_type` срезает ведущие кириллические слова до первой не-кириллицы.
2. `extract_bearing_codes` вытаскивает «код»: убирает ГОСТ/DIN, размеры `25x52x15`, внутренние коды,
   описательные слова, транслитерирует кириллицу в латиницу и **склеивает все оставшиеся токены через `-`**.
3. `extract_primary_number` берёт первое число из 3+ цифр (иначе из 2+).
4. Сравнение: нормализованный Левенштейн по полному коду, плюс правило по «главному номеру»:
   - номера равны → `combined = max(full_sim, 0.90)`;
   - номера разные → `min(full_sim, 0.75)`.
5. Скраперы сравнивают результат с порогом **0.85** (в двух — с **0.5**).

### Главный вывод

Из-за правила `max(full_sim, 0.90)` при пороге 0.85 алгоритм фактически сводится к бинарному
«совпал ли главный номер»: **любое совпадение номера даёт ≥ 0.90 и проходит**, а любое несовпадение
упирается в 0.75 и не проходит. Левенштейн по полному коду почти ни на что не влияет, а суффиксы
(`2RS`, `ZZ`, `C3`, `P5`, `-2RS1`) **не различаются вообще**.

Следствия:
- `6205` и `6205-2RS` — «похожи» на 0.90 (для подшипника это разные товары: открытый vs закрытый);
- `6205-2RS` и `6205-ZZ` — тоже 0.90 (разный тип уплотнения);
- `6-7208А` и `7208` — 0.90 (разный класс точности по ГОСТ);
- при этом `06205` и `6205` — 0.75 и **не проходят**, хотя это один и тот же подшипник
  (исправлено: нормализация ведущих нулей в `compare.py`, см. §5).

## 3. Критические дефекты

### 3.1. Мёртвые регулярки: `$` вместо скобок

`compare/compare.py:62`, `:104`, `:105`:

```python
s = re.sub(r'\s*$[A-ZА-Я][A-ZА-Яa-zа-я\s/+\-.]*$\s*$', '', s)   # «убрать (БРЕНД) в конце»
alt_codes = re.findall(r'$([A-Z0-9][A-Z0-9\-/]*)$', s.upper())  # «альтернативные номера в скобках»
s = re.sub(r'\s*$[A-Z0-9][A-Z0-9\-/]*$', '', s)
```

`$` — якорь конца строки. Шаблон `$[...]` не может совпасть ни разу (после конца строки нечего
матчить), поэтому:
- бренд в скобках не удаляется;
- **альтернативные номера из скобок не извлекаются никогда** (`alt_codes` всегда пуст);
- третий `re.sub` тоже не срабатывает.

То же самое в `compare/extract.py:111` и `:160`. Судя по смыслу, там должны были быть `\(` … `\)`.

Практический эффект — ложные отказы: `"Подшипник 6-7208А (30208)"` против найденного `"30208"`
не совпадёт никогда (номер 7208 vs 30208 → 0.75 → отказ), хотя альтернативный номер совпадает точно.

### 3.2. Порог 0.5 отключает проверку по номеру

`scrapper/podshipnik_ru_scrapper.py:54` и `scrapper/podshipnikru_scrapper.py:50` — `sim >= 0.5`,
остальные — `>= 0.85`. Так как при разных номерах результат ограничен сверху `min(full_sim, 0.75)`,
порог 0.5 пропускает **почти всё**: `"6205"` против `"6306"` даёт 0.75 и принимается.
То есть в этих двух скраперах алгоритм похожести не защищает от неверного товара.

### 3.3. Пустые коды → 0.0

`compare/compare.py:166`:

```python
if not codes1 or not codes2:
    return 0.0
```

Если в описании нет цифр (например, `"Подшипник игольчатый"`), код пустой — и **две одинаковые
строки получают 0.0**. `remove_bearing_type` легко возвращает `''` для чисто кириллического текста.
Нужен fallback на сравнение нормализованных строк.

### 3.4. Мёртвая ветка и жёсткий «обрыв» 0.75

`compare/compare.py:180-184`: ветка `num_sim >= 0.95` практически недостижима — при разных числах
длины 4+ Левенштейн даёт ≤ 0.8. А `min(full_sim, 0.75)` — обрыв: одно отличие в длинном коде
обнуляет всё остальное совпадение.

### 3.5. `extract_primary_number` и ведущие нули

`compare/compare.py:120`: `"06205"` → `"06205"`, `"6205"` → `"6205"`, `num_sim = 0.8 < 0.95` → отказ.
Нужна нормализация числа (убрать ведущие нули) и сравнение как строк, а не как «похожесть».

### 3.6. `BRANDS` и регистр

`compare/compare.py:21-32`: в множестве есть `'Feltre'`, `'John Deere'`, `'ВОЛЖСКИЙ СТАНДАРТ'`.
Фильтр (`:113`) сравнивает токены, полученные из `s.upper()`, — `'FELTRE'` в множестве нет,
`'JOHN DEERE'` как один токен не существует вовсе. Бренды с пробелами/смешанным регистром не удаляются
и попадают в код, раздувая различия.

### 3.7. Склейка токенов через `-` делает порядок значимым

`"2RS 6205"` и `"6205 2RS"` дают разные коды (`2RS-6205` / `6205-2RS`), и только правило
«равный номер ≥ 0.90» спасает сравнение. Правильнее разбирать код на `(база, суффиксы)` и сравнивать
множества суффиксов, а не строку.

### 3.8. Docstring не соответствует поведению

`compare/compare.py:158-160` обещает вернуть `(сходство, вердикт)`, а возвращает `float`.
`compare/extract.py` в docstring обещает работу с альтернативными номерами, которой нет (см. 3.1).

## 5. Что предлагаю поменять

### P0 — корректность сравнения

1. Починить регулярки: `$(` → `\(`, `$` → `\)`, вернуть извлечение альтернативных номеров.
2. Свести порог к одной константе `THRESHOLD = 0.85` и убрать 0.5.
3. Заменить «равный номер ⇒ 0.90» на явную модель: **база + суффиксы**.

Эскиз (не запускался, нужен прогон на реальных данных):

```python
THRESHOLD = 0.85

def split_code(code: str) -> tuple[str | None, tuple[str, ...]]:
    """'6205-2RS-C3' -> ('6205', ('2RS', 'C3'))"""
    tokens = [t for t in re.split(r'[-/]', code.upper()) if t]
    number = next((t for t in tokens if t.isdigit()), None)
    if number is None:
        m = re.search(r'\d{2,}', code)
        number = m.group(0) if m else None
    if number:
        number = number.lstrip('0') or number
    suffix = tuple(t for t in tokens if t != number)
    return number, suffix

def suffix_similarity(a: tuple[str, ...], b: tuple[str, ...]) -> float:
    if not a and not b:
        return 1.0
    if not a or not b:
        return 0.0
    return sum(max(levenshtein_norm(x, y) for y in b) for x in a) / len(a)

def pair_score(c1: str, c2: str) -> float:
    if c1 == c2:
        return 1.0
    n1, s1 = split_code(c1)
    n2, s2 = split_code(c2)
    if n1 and n2:
        if n1 != n2:
            return 0.4 * levenshtein_norm(n1, n2)      # всегда ниже порога
        return 0.70 + 0.30 * suffix_similarity(s1, s2)
    return 0.9 * levenshtein_norm(c1, c2)              # один код без номера
```
